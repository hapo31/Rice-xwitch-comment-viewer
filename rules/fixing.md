# 修正作業

既存ファイル、既存機能、設定、文書の修正を始める前に、このルールを読みます。

## 作業場所

- 原則として、対象ブランチの現在の基点から一時ブランチと git worktree を作り、その worktree 内だけで修正する。
- ユーザーから「すぐに動作確認したい」と明示された場合に限り、通常の workspace で作業する。その場合も、編集を始める前に修正専用ブランチを作る。
- 作業開始前に `git status`、現在のブランチ、既存 worktree を確認する。ユーザーの未コミット変更を移動、破棄、stash、上書きしない。
- 一つの修正単位を一つのブランチに隔離し、無関係な変更を commit に含めない。

## 完了と後片付け

関連する PR または Issue がある修正では、作業やマージが完了しても、それらが open の間は worktree と修正用のローカル／リモートブランチを保持します。関連する PR と Issue がすべて close された後にだけ後片付けを行います。

関連する PR または Issue がない修正では、修正、検証、レビュー、必要な commit を終え、成果が対象ブランチなど失われない場所へ保存された後に後片付けを行います。

後片付けが可能になったら、次を行います。

1. 一時 worktree が clean であり、必要な commit が保存先から到達可能であることを確認する。
2. 一時 worktree を削除する。
3. 修正用のローカルブランチを削除する。
4. 修正用のリモートブランチを作成していた場合は削除する。
5. `git worktree list` とローカル／リモートの branch 一覧を確認し、今回の一時リソースが残っていないことを確認する。

未統合の成果を指す唯一の worktree やブランチは削除しません。関連する PR または Issue がある場合は、worktree、ローカルブランチ、リモートブランチのいずれも、それらがすべて close される前に削除しません。

## 安全条件

- worktree、ローカルブランチ、リモートブランチは、今回作成した正確な名前を再確認してから削除する。
- 他の作業者、既存 PR、未コミット変更が使用している worktree やブランチは削除しない。
- base branch の更新で修正内容や要件が変わった場合は、自動的に統合せず差分を再確認する。
